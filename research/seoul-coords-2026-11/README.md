## 키 처리 (clo 조건 ③)

서울 API는 평문 `http://openapi.seoul.go.kr:8088/(인증키)/...`이고 키가 URL 경로에 들어간다. kapt-fill의 호출부를 옮기지 않고 새로 썼다.

| 조건 | 어떻게 | 시험 |
|---|---|---|
| 키는 호출 스텝 env에만 | 워크플로에 `secrets.`가 한 번, `fetch` 스텝뿐. 스크립트는 읽자마자 환경에서 지운다. 그 스텝에 제3자 코드가 없도록 `npm ci`를 하지 않는다(외부 패키지 0) | 워크플로 시험 |
| URL을 로그·예외·요약·아티팩트에 안 씀 | URL은 `callOnce` 지역 변수뿐. 오류는 분류·코드·HTTP 상태·네트워크 오류 이름만. 서버 메시지·응답 본문을 남기지 않는다(서버가 주소를 되비칠 수 있다) | 500 본문에 주소를 되비치는 스텁, 연결 실패 |
| 리다이렉트 불허 | `redirect: "manual"`. 3xx면 멈춘다 | 302 스텁, 두 번째 요청 0 |
| 업로드 전 키 0 검사 | 파일을 쓰기 **전에** 출력 문자열에서 원문·인코딩·영숫자 12자 조각을 찾는다 | 응답 값에 키를 넣은 스텁 |
| 노출 감지 시 중단 | 값을 하나도 쓰지 않고 종료 5, `key-exposure-stop.json`만 남긴다. 아티팩트 이름이 다음 dispatch를 막는다. 소유자에게 재발급 요청 | 같음 |
| 호출 상한, 1회 1,000건 이하, 재시도 없음 | 아래 표 | 쪽 범위 기록, 500에 1회 |

**남는 위험.** 전송 구간은 평문이라 키가 네트워크에 그대로 지난다. 공식 안내의 주소가 이것뿐이다(clo 확인: 키 없이 https는 `:8088` TLS 오류, `:8443` 시간초과). 측정 뒤 키를 계속 쓸지는 cto 기준으로 정한다.

## 저장 범위 (clo 조건 ①)

집계뿐이다: 채운 수, 값표(구·분류·호선·`USE_YN` 등), 글자를 지운 모양, 분위수, 구간표, 겹침 수. 응답 원문, 단지별 행, 좌표, 개별 거리, 이름, 단지 코드, 연락처(`TELNO`, `FXNO`), `EPIS_MNG_NO`를 파일·로그에 쓰지 않는다. 최솟값·최댓값은 단지 하나의 값이라 남기지 않고 구간표로 본다. 그래서 나중에 원본으로 다시 셀 수 없다. 역 이름은 모양과 고유 개수(`stations.distinctNames`)만 남긴다.

서울시 후원·관계로 오인될 표현을 쓰지 않는다. 이 통과는 측정까지다. 근거표·점수·화면에 쓰거나 단지별 값을 저장하면 clo가 먼저 별도로 대조한다.

## 이미 본 값 (pm 잠금에 적을 것)

`offline-check.out`. 호출 0회, K-apt 엑셀 2026-09-25분을 서울 행 자리에 넣고 좌표를 다 찼다고 친 값이다. **서울 값의 예측이 아니다**(서울은 위키 2,893행, 엑셀 3,189). 계산 재현 확인이 목적이다: 지번 81.78%는 옛 81.9%, 지번+도로명 88.87%는 옛 89.1%와 가깝다.

| 경로 | 거래 붙음 | n≥3 칸 코드 하나 | n≥3 칸 여러 코드 |
|---|---|---|---|
| 지번 | 81.78% | 2,563 / 3,058 = 83.81% | 115 |
| 도로명(전월세 다리) | 86.94% | 2,650 / 3,058 = 86.66% | 175 |
| 지번 → 도로명 | 88.87% | 2,767 / 3,058 = 90.48% | 117 |

K-apt 지번을 안 거치는 도로명 경로가 지번보다 칸을 더 붙인다. 엑셀 주소 기준이고, 서울 응답의 도로명 칸 채움은 모른다.

## pm이 호출 전에 잠글 것

1. **어느 경로로 판정하나.** 거래·칸을 어떤 경로의 값으로 읽는지. 호출 뒤에 고르지 않는다. 지번 칸이 비면 그 경로는 0이다. 이름 경로를 넣을지.
2. **실3.** PREREG 그대로 `overlap.cellsNge3.<경로>.uniqueWithCoord / overlap.denominators.cellsNge3` ≥ 80%(80~95%면 충족률을 적는다). #823식 거래 겹침을 문턱으로 쓸지 참고로만 둘지.
3. **여러 코드.** `ambiguousSpread.within100m`을 분자에 넣을지.
4. **좌표 유효.** 지금 코드는 서울 사각형 안이면 유효이고 뒤바뀐 값은 뒤집어 쓴다. 이대로인지. 경위도(`kinds.lonlat`+`swapped`) 비율 문턱.
5. **형식.** 자릿수 문턱(소수 3자리면 약 100m 격자). 모양표 정규식.
6. **쏠림·위치 품질.** 같은 좌표 공유(`duplicates`), 구 중심 거리 구간에 문턱을 걸지.
7. **행 범위.** `USE_YN`이 `Y`가 아닌 행(탈퇴 등)을 칠지. `uniqueWithCoord`와 `uniqueWithCoordUseYes` 중 어느 쪽인지.
8. **역 쪽.** `ROUTE` 범위 문턱(예: 서울 안 노선이 빠지면 미달). 역 좌표 채움 문턱.
9. **판정 못 함.** `result: null`이면 판정 못 함, 미달과 구분.
10. **실5는 이 측정으로 안 끝난다.** 단지별 값을 남기지 않으니 100단지 대조 재료가 없다. 일치 정의·대조 출처를 새 버전으로 적고, 단지 값을 받으면 clo 별도 대조가 먼저다.

## 미확인

- 일반 키 일 호출 상한.
- `XCRD`·`YCRD`·`LAT`·`LOT` 좌표계. 값 범위로 경위도·투영까지만 가른다. **경위도라도 측지계(WGS84·Bessel, 서울에서 약 300m 차이)는 값으로 못 가른다.** 「직선 n m」의 뜻이 달라지는 차이다. 역 쪽은 OA-22534와 대조하면 드러날 수 있다. 단지 쪽은 다른 출처와 대조가 필요하다.
- GitHub Actions 러너(해외 IP)에서 `openapi.seoul.go.kr:8088`에 닿는지. 막히면 `network`로 멈추고 값이 없다.
- 응답의 실제 모양(JSON 묶음·필드 값). 위키는 샘플 키로 두 서비스 2줄씩만 봤다. 시험은 명세로 만든 스텁이다.
- OA-21232 호선 범위, 인증키 신청 화면 약관, 공공데이터법 본문, 관리주체 입력값의 제3자 권리(clo 미확인 그대로).
