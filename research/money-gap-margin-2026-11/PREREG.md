## 후보 규칙 (`rules-908.mjs`)

공통: 공개 파일의 `low`·`high`·`change` 는 바꾸지 않는다. 판정은 반올림한 끝값(만원 정수, 공개 파일 그대로)을 반올림하지
않은 폭과 견준다. 폭은 모두 0 이상이라, 「늘었다」로 정한 쌍은 화면의 구간 하단이 늘 0보다 크다(줄었다도 같다).

| 후보 | 늘었다 | 줄었다 | 폭을 정한 문장 |
|---|---|---|---|
| (라) 규칙 없음 | low > 0 | high < 0 | 지금 인라인 네 곳(`docs/switch-house.html` 157·166·207·215행) 그대로. |
| (가) 고정 폭 | low ≥ 50 | high ≤ −50 | 구간 끝이 화면에 0으로 적히면 늘었다·줄었다고 말하지 않는다. 두 언어 중 거친 영어 화면은 금액을 백만원 단위로 적어(`eokText`: ₩ round(n/100) M) 끝이 50만원 미만이면 「₩0M」이다. 한국어 화면(만원 단위)에서는 (라)와 같다. #858 의 원칙 「판정은 화면에 적힌 값과 맞아야 한다」를 끝값에 건 것. |
| (나) 구간 폭 비례 | low > C·(high − low) | high < −C·(high − low) | 끝값의 추첨 표준오차를 정규분포로 근사하면 구간 폭의 κ배다. κ = √(0.05·0.95/4000) ÷ φ(1.645) ÷ (2·1.645) ≈ 0.010158. 끝이 0에서 그 표준오차의 z = 1.645배(한쪽 5%, 구간의 각 끝과 같은 수준) 안이면 말할 수 없다. C = z·κ ≈ 0.016710. 이론값이고 자료에 맞춘 값이 아니다. |
| (다) 씨앗 사이 흩어짐 | low > 1.645·sd_low | high < −1.645·sd_high | 빌드가 지금 씨앗 말고 씨앗 3개(20261001 + 7919·j, j = 1..3)로 금액 간격을 더 돌려 네 끝값의 표본표준편차 sd 를 낸다(자유도 3). 공개 끝값은 지금 씨앗 그대로. |
| (다′) 추가 재추출 없는 흩어짐 | low > 1.645·se_low | high < −1.645·se_high | 같은 정렬된 4,000개에서 순서통계량으로 끝값의 추첨 표준오차를 낸다. 참 분위수 아래로 떨어지는 값의 수는 이항(4000, 0.05)이고 그 표준편차가 √(4000·0.05·0.95) ≈ 13.8개라, m = 14 로 se_low = (sims[214] − sims[186]) / 2, se_high = (sims[3814] − sims[3786]) / 2. |

(다′)는 이슈 본문의 후보 넷에 이 문서가 측정 전에 더한 것이다. (다)를 이슈 문장대로 씨앗을 더 돌려 하면 더 돌리는
씨앗이 하나여도 금액 계산 한 번(PR #912 실측 27.4~28.9초)이 더해져 아래 7.7초 여유를 넘는다. 같은 양(끝값의 씨앗 사이
흩어짐)을 추가 재추출 없이 재는 방법을 같이 올린다. cto·cpo 가 측정 전에 빼라고 하면 빼고 재며, 그때는 그 수정 커밋이
측정 전 sha 가 된다.

### 규칙마다의 기준 답

뒤집힘은 **같은 규칙**의 기준 답과 견준다. 규칙이 경계를 0에서 다른 곳으로 옮기기만 하면 새 경계 근처의 쌍이 추첨으로
갈린다. 지금 규칙(라)의 기준 답과 견주면 「말할 수 없다」로 바꾼 쌍은 뒤집힘으로 세지 않게 되어, 경계만 옮긴 규칙이
유리해진다. 그래서 그렇게 세지 않는다.

- (라)·(가): 기준 끝값에 같은 규칙.
- (나): 기준 끝값과 기준의 폭(high − low).
- (다)·(다′): 기준 끝값과, 폭 = 1.645 × (씨앗 20개의 4,000번 끝값 표본표준편차) — 4,000번 끝값의 참 흩어짐 대용. 기준
  20,000번의 순서통계량은 20,000번의 흩어짐이라 쓰지 않는다.
- (다)의 후보 실행: 씨앗 k 의 빌드는 씨앗 묶음 {k, k+1, k+2, k+3}(20 안에서 돌림)의 끝값으로 sd 를 낸다. k = 0 이면 빌드가
  실제로 쓸 j = 1..3 과 같다.

## 지표 (입력마다, `analyze-908.mjs`)

1. **뒤집힘** F_Q(k): 쌍 가운데 Q(4,000번, 씨앗 k)의 답이 Q(기준)의 답과 다른 쌍 수. 씨앗 20개의 중앙값(10·11번째 평균)과
   최댓값.
2. **말할 수 있는 쌍 감소** L_Q = S_(라)(기준) − S_Q(기준). S 는 답이 「말할 수 없다」가 아닌 쌍 수. 보조로 씨앗별 감소의
   중앙값.
3. 보조(판정에 쓰지 않음): 씨앗 k = 0 대비 뒤집힘, 늘었다↔줄었다 반대 뒤집힘 수, 한 번이라도 뒤집힌 쌍과 횟수.
4. **빌드 시간 증가**(cto 조건 3, `time-908.mjs`): 이 머신, 입력 A, 각 3회 중앙값, 1분 부하 평균을 시작·끝에 적는다. 다른
   계산과 겹치지 않게 따로 돌린다. (가)·(나)는 규칙을 거는 단계, (다′)는 순서통계량을 더 읽는 구현과 읽지 않는 구현
   (#858 `fast-858.mjs` moneyFast)의 차 + 규칙 단계, (다)는 「지금 씨앗 + 씨앗 3개 + 규칙」 − 「지금 씨앗」.
5. **날마다의 뒤집힘**(이슈 「할 일」 넷째 줄, 기록만): 입력 B → A, 두 입력 모두에 있는 쌍. 화면 답 바뀜 P(지금 씨앗),
   기준 답 바뀜 D. 데이터 몫 = P ∩ D, 추첨 몫 = P \ D(화면만 바뀜) + D \ P(기준만 바뀜). 같은 씨앗 k 를 두 날에 쓴 20개의
   추첨 몫 중앙값·최댓값도 적는다. 두 입력의 두 시기가 다르면 그 사실을 적는다(그때 데이터 몫에는 시기 이동이 들어 있다).

## 판정 규칙 (결과 보기 전에 고정)

**통과** — 아래를 모두 채운 후보:

- a. 입력 A·B 각각에서 뒤집힘 중앙값 ≤ 1, 최댓값 ≤ 3(#858 과 같은 문턱).
- b. 입력 A·B 각각에서 말할 수 있는 쌍 감소 L ≤ **9쌍**. 183(2026-11-15 원본·지금 씨앗·200번 공개값, 4,000번은
  184 — #858 판정 댓글 4·PR #912 본문)의 5%를 내린 수다. 180~199의 5%는 모두 내리면 9라, 입력 B의 (라) 기준 S가 이 범위면
  상한은 같다. 5%는 90% 구간이 한쪽 끝에서 이미 틀릴 수 있다고 허용하는 몫이다 — 추첨 흔들림을 고치려고 그보다 많은 답을
  버리면 고치는 것보다 치르는 것이 크다. A 의 S 에 따라 바꾸지 않는다.
- c. 빌드 시간 증가 ≤ **7.7초**(30 − 22.3초, PR #912 본문 실측). 넘으면 그 후보는 탈락(cto 조건 3).

**선택:**

1. 통과한 후보가 여럿이면 두 입력의 감소 합 L_A + L_B 가 가장 작은 것. 같으면 뒤집힘 최댓값 합, 그다음 중앙값 합, 그다음
   (라) → (가) → (나) → (다′) → (다) 순서(단순한 것 먼저). 문턱이 안정을 이미 보장하므로 그 위에서는 답을 덜 버리는 쪽을
   고른다.
2. (라)는 B에서 이미 중앙값 2로 a를 넘지 못한다. (라)는 3번(무통과)으로만 뽑힌다
3. **하나도 통과하지 못하면 (라)**(규칙 없음, method 문장만). 완료 조건 4대로 #858 이 `docs/method.html` 238행에 적은

   (라)로 가면 method 238행(ko)·546행(en) 흔들림 문장은 덧붙이지 않는다. 씨앗 20개 기준 R0(입력 A)의 뒤집힘 최댓값이 3쌍을 넘거나 중앙값이 2쌍을 넘을 때만 그 문장의 숫자·쌍 총수·날짜를 R0 값으로 바꾸고, 그 밖에는 #908 종결 댓글에 R0 값과 「문장 유지」 한 줄만 남긴다(pm 판정, #908).

  그 필드를 읽고, 없으면 지금 규칙으로 돌아간다. 공개 low·high·change 는 바꾸지 않는다(구간을 잘라 규칙을 표현하지 않는다).
  인라인 증가는 장당 +400 B 이하(S6).
- 허용 파일은 cto 조건 5. 정정 항목이 생기면 #913 병합 뒤.
- (가)는 영어 화면의 금액 단위에 묶인다. `eokText` 의 단위가 바뀌면 X 를 다시 등록한다.

## 실행 순서

입력마다 작업 트리를 따로 꺼낸다(`git checkout <커밋> -- raw` 는 그 커밋에 없는 파일을 남기므로 쓰지 않는다). 코드는
`8eb314f7`, 이 폴더는 이 문서를 커밋한 sha(`<등록 sha>`)에서 가져온다. 작업 트리는 저장소 옆 `../jipgye.worktrees/908-A`·
`908-B`, 첫 줄은 저장소 루트에서 시작한다. `D=research/money-gap-margin-2026-11`. `git worktree add` 에는 `timeout -k 10 600`
을 붙이고, git 이 D 상태로 멈추면 다시 시도하지 않고 멈춘 뒤 cto 에 넘긴다.

```sh
# 실행 로그 첫 줄들
echo "등록 <등록 sha> · A 데이터 <A 데이터 커밋> · A 원본 <A 원본 커밋>"
dmesg | grep -c 'hv_storvsc.*0x28'
# 입력 B: 8eb314f7 트리 그대로
timeout -k 10 600 git worktree add --detach ../jipgye.worktrees/908-B 8eb314f7 && cd ../jipgye.worktrees/908-B
git rev-parse HEAD
git restore --source=<등록 sha> --staged --worktree -- $D
node $D/prep-908.mjs B money200 && node $D/verify-908.mjs B
# 입력 A: 데이터 커밋을 꺼내고 코드만 8eb314f7 로(그 커밋의 sha 를 출력 첫 줄에 적는다)
timeout -k 10 600 git worktree add --detach ../908-A <A 데이터 커밋> && cd ../908-A
git rev-parse HEAD
git restore --source=8eb314f7 --staged --worktree -- scripts research/district-change-rounds-2026-11
git diff --cached --quiet 8eb314f7 -- scripts research/district-change-rounds-2026-11 || exit 1
git restore --source=<등록 sha> --staged --worktree -- $D
node $D/prep-908.mjs A full && node $D/verify-908.mjs A
cp ../908-B/$D/input-908-B.json $D/
# 기준 2개 + 후보 40개
xargs -P 4 -L 1 sh -c 'node '"$D"'/run-908.mjs "$0" "$1" "$2"' < $D/jobs-908.txt || exit 1
# 빌드 시간: 위가 끝난 뒤 다른 계산 없이
uptime
node $D/time-908.mjs 3 | tee $D/time-908.out
node $D/analyze-908.mjs | tee $D/analyze-908.out
```

`input-908-*.json`·`out/` 은 커밋하지 않는다(`.gitignore`). `analyze-908.out`·`time-908.out` 은 결과 커밋에 넣는다. 끝나면
두 작업 트리를 지운다.
