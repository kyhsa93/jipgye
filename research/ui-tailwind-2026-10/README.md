### 8-3. 일하는 방식 (로컬 메모리에만 있던 규칙)

원문은 비공개 저장소 `kyhsa93/agents`의 README 「협업 절차」다. 아래는 이 작업에 쓰인 것만 옮긴 요약이다.

- **지시는 ceo 역할을 먼저 거친다.** 소유자가 이 계정의 프로젝트에 새 일을 지시하면 메인 세션은 ceo 역할 에이전트에게 먼저 넘겨 분해·계획을 받고, 그 계획대로 역할 에이전트(pm·cpo·cto·po·cmo·engineer)를 부른다. 에이전트끼리는 서로 부르지 못하므로 메인 세션이 결과를 옮긴다. 역할은 메인 세션이 연기하지 않고 정의 파일을 읽은 별도 에이전트가 맡는다.
- **소유자에게 먼저 묻는 것은 다섯 가지뿐이다**: 돈이 드는 것, 소유자 개인의 법적 위험, 정체성 변경(DIRECTION 1부), 소유자 계정 로그인이 필요한 것, 기기 조작(로컬 cron·예약 작업 등록 포함). 그 사안이 걸린 작업을 **시작하기 전에** 묻는다. 나머지는 묻지 않고 진행하고 결과를 보고한다.
- **PR 병합은 cto 판정으로 집행한다.** cto 역할이 head SHA를 적어 "머지 승인"을 내면 메인 세션이 소유자 확인 없이 squash로 병합한다. "수정 요청"이거나 판정이 없으면 병합하지 않고, 판정 뒤 head가 바뀌면 다시 검증받는다. engineer는 PR을 열기만 한다(자가 승인·병합·main 직접 push 금지).
- **이슈 흐름**: pm이 이슈를 쓰고 우선순위 라벨(`지금`·`다음`·`후순위`, 열린 `지금`은 5건까지)을 붙인다 → cpo가 이슈마다 교차검증 댓글(적합 / 보완 필요 + `CPO: 보완필요` 라벨) → 적합이 달린 것만 engineer가 집는다 → cto가 PR을 검증한다. `사람 필요`·`오너결정필요` 라벨은 에이전트가 집행하지 않는다.
- **커밋·PR 문구**: `Co-Authored-By`·`Claude-Session`·"Generated with Claude Code" 줄을 넣지 않는다. PR 본문은 단계 PR이면 `Refs #N`(닫는 것은 마지막 PR이나 pm).
- **유료 API를 쓰지 않는다.** 어떤 자동화에서도 `claude -p`나 `ANTHROPIC_API_KEY` 과금 호출을 쓰지 않는다. 비용이 작아도 같다.
- **확인하지 못한 것은 '확인 못함'으로 적는다.** 합격선·문턱은 결과를 본 뒤에 바꾸지 않는다.
- **병합 시각**: 사이트·워크플로를 바꾸는 병합은 KST 낮에, `digest-pipeline`(Daily update·Summarize) 실행이 0건일 때 한다(실행 중에 main이 앞서면 그 실행의 푸시가 거절된다).
- Search Console·GA·애드센스 콘솔은 소유자만 볼 수 있다. 에이전트가 로그인을 시도하지 않는다.
