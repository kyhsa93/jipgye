# K-apt 채움률·역 값 측정 (#823)

주인 data-engineer, 검토 cto, 약관 clo. 값을 근거표에 먼저 쓰는지는 pm이 판정한다. 아직 호출하지 않았다.

- `measure.mjs`: `plan`(호출 없음), `guard`(재실행 거부), `fetch`(호출, 요약만 저장)
- `kapt-fill-measure.yml`: dispatch 전용 워크플로 초안. clo 대조 뒤 `.github/workflows/`로 옮긴다.
- `measure.test.mjs`: 스텁 서버 시험. `node --test research/kapt-fill-2026-11/measure.test.mjs`
- `plan.out`: `plan` 출력

## 무엇을 재나

| 이슈 항목 | 재는 값 | 범위 |
|---|---|---|
| 1. 기존 키로 호출되는가 | `PUBLIC_DATA_PORTAL_API_KEY`만. 인증 오류면 코드·상태만 남기고 멈춘다 | 서비스별 첫 호출 |
| 2. 채움률·형식 | `kaptdWtimesub`, `subwayLine`, `subwayStation` | 상세 표본(구별 비례, 고정 시드) |
| 2. 채움률·형식 | `kaptdaCnt`, `hoCnt`, `hhldCnt`, `kaptUsedate` | 기본 정보 전수 |
| 3. 실거래 겹침 | `kaptAddr` 지번 = 구+법정동+지번. 단지 키·칸·거래·한 지번 여러 코드 | 기본 정보 전수 × `raw/sale` |

겹침은 이슈대로 지번 경유만 잰다. 전월세 도로명 경유까지 넣은 옛 값(거래 89.1%, `count5.py`)과 직접 견주려면 지번 쪽 값(81.9%)과 견준다.

**명세와 이슈의 차이(2026-11-03 페이지 명세).**

- `hhldCnt`는 15058453 응답 명세에 없다. 세대수는 `kaptdaCnt`, 호수는 `hoCnt`다. 셋 다 세어 드러낸다.
- `kaptdWtimesub`의 설명은 「지하철역 거리」다. 「도보 시간」이라는 말은 명세에 없다. 값의 단위는 히스토그램을 본 뒤 적는다.
- 키 파라미터가 `getAphusDtlInfoV5`만 `ServiceKey`, 나머지는 `serviceKey`다. 명세대로 부른다.
- 코드표는 페이지에 없다. 22·30~33은 `scripts/official-price-api.ts`와 같고, 20·23·12는 포털 공통 코드로 넣었다(이 두 페이지로 확인하지 못함). 형식이 어긋나면 멈춘다.

## 호출량

페이지 표기: 두 서비스 모두 「개발계정 : 5,000」, 「개발단계 : 자동승인」. 단위(서비스·오퍼레이션)는 페이지에 없어 **서비스 합산**으로 잡았다.

| 항목 | 호출 |
|---|---|
| 서울 단지 | 3,189(엑셀 2026-09-25분 고유 코드. `kapt-seoul.json` 3,336행, 고유 3,189. API 값은 첫 목록 호출에서 정해진다) |
| 단순 전수 | 3,189 × 2 = 6,378 > 5,000. **하루에 안 끝난다** |
| 15057332 목록 | 페이지당 1,000이면 4회. 상한 60 |
| 15058453 계획 | 기본 전수 3,189 + 상세 표본 1,511 = 4,700. 일시 오류 여분 100. 상한 4,800 |
| 합계 상한 | 4,860 < 5,000 |

- 표본 폭: 상세 1,511이면 95% 폭 최대 ±1.83%p(`plan.out`). 재는 일에는 충분하다.
- 단지가 3,300을 넘으면 기본 3,300 + 상세 1,400으로 자르고, 겹침은 하한으로 적는다.
- 속도 초당 1회 이하, 약 81분 이상. 스크립트 시간 상한 150분, 잡 165분.
- 같은 키를 쓰는 공시가격 수집(`official-price-api.yml`, 15134735)과는 서비스가 달라 한도가 따로일 것으로 본다(미확인). 한도 코드를 받으면 양쪽 모두 멈출 뿐 값이 틀어지지는 않는다.

## 저장 범위

요약뿐이다: 채운 수, 값 분포, 모양, 분위수, 겹침 수. `kaptdWtimesub`·`subwayLine`은 값별 건수(상위 40), `subwayStation`은 모양과 고유 개수만 남긴다. 단지 코드·이름·주소·연락처와 응답 원문은 파일·로그에 쓰지 않는다. 그래서 나중에 원본으로 다시 셀 수 없다.

## 멈춤과 재실행

- 인증 오류(HTTP 401·403, 코드 20·30~33): 다시 부르지 않고, 다른 키로 넘어가지 않고, 코드·상태만 남긴다. 한도(22·23·429)와 규격(12)도 같이 멈춘다.
- 일시 오류만 한 번 다시 부른다. 10단지 연속 실패면 멈춘다.
- 재실행 거부: 다시 실행(attempt>1), `kapt-fill` 아티팩트 있음, 결과 파일 있음이면 호출 전에 거부한다.
- 조기 중단(두 오퍼레이션 확인 전 멈춤)은 `kapt-fill-early-stop` 아티팩트라, 사람이 원인을 고치고 `resume_after_early_stop=yes`로만 다시 돌린다. 2회가 상한이다. 한 번에 최대 63회.
- 아티팩트 보관 30일. 결과는 그 안에 이 폴더로 옮긴다. 옮긴 뒤에는 결과 파일이 거부를 이어받는다.
